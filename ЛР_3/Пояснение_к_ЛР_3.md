# ЛР №3: основы языковых моделей и эмбеддинги

## Что сдавать

Основная работа — **`ЛР_3_Основы_языковых_моделей.ipynb`**.
Для повторного запуска рядом с ним должна находиться папка `data` с файлом
**`greenfield_town.json`**. Удобнее отправить `ЛР_3_готовая_работа.zip`, где
ноутбук и данные уже расположены правильно.

В отличие от предыдущей ЛР, этот шаблон читает профиль из отдельного JSON.
Для просмотра без запуска есть HTML, а для подготовки к защите — это пояснение.
В архив также включены результаты и список версий библиотек.
Исходные лекции и Harbor example сдавать не требуется.

В исходном комплекте преподавателя модуль называется «ЛР №01»;
в текущей папке курса он выполнен как третья лабораторная.

Весь обязательный расчёт выполнен на **Greenfield Town**, который прислан

Первое вложение — готовый пример **Harbor Town**, второе — студенческий

## В чём заключалось задание

Нужно было реализовать шесть тем: представление текста мешком слов,
нейросетевой классификатор, skip-gram-эмбеддинги, BPE, счётную языковую
модель и метрики качества. После каждого раздела требовалось написать,
что получилось, почему и чего из этого нельзя заключить.

Затем нужно было запустить обязательное мини-портфолио, пройти девять
проверок и заполнить паспорт результата: вход, результат, проверка,
ограничение и действие для переноса на другую задачу.

Это несколько самостоятельных экспериментов. В этой работе BPE не подаётся
на вход skip-gram, а счётная модель не использует эмбеддинги.

## Что такое эмбеддинг

Эмбеддинг — числовой вектор слова. Здесь каждому из 33 слов сопоставлены
12 обучаемых чисел. Их не задают вручную как признаки «человек», «место»
или «профессия»: векторы меняются во время обучения на соседних словах.

Модель skip-gram получает центральное слово и учится предсказывать его
контекст. Например, для строки `the gardener waters the garden` и окна 2
у `gardener` появляются пары с соседями `the`, `waters` и ещё одним `the`.
Число появлений сохраняется: это статистика соседних позиций.

После обучения близость сравнивается по косинусному сходству:
направления векторов сопоставляются после нормировки их длин.
У `gardener` получились соседи:

- `garden` — 0,572889;
- `baker` — 0,463809;
- `gate` — 0,459216.

Это наблюдение о маленьком корпусе, а не доказательство синонимии.
`gardener` — человек, `garden` — место, но они встречаются с похожими
словами `waters`, `opens`, `visits`, `the`.
Профессии также используются в похожих шаблонах предложений.

Таблица эмбеддингов имеет размер 33×12. На рисунке показаны только две
главные компоненты PCA, поэтому его расстояния не полностью совпадают
со сходством исходных векторов. Точные соседи указаны в численном выводе.

Словарь классификатора содержит 51 слово, а словарь эмбеддингов — 33:
они построены по разным частям профиля и не обязаны совпадать.

## Как связаны остальные части

**BoW** превращает документ в бинарный вектор присутствия слов.
Он игнорирует порядок и повторения. Поэтому `garden gate opens`
и `opens gate garden` имеют одинаковый BoW, хотя порядок различается.
Биграммы показывают соседние пары, но не решают проблему всех дальних связей.

**Классификатор** принимает 51 признак, строит 24 скрытых признака с ReLU
и возвращает три логита. Логиты — ещё не вероятности.
`CrossEntropyLoss` сама включает устойчивое преобразование логитов,
поэтому в `forward` отдельного Softmax нет.
`argmax(dim=1)` выбирает класс отдельно для каждого документа.

В ручном примере логиты `(2, 1, 0.5)` дают вероятности примерно
`(0.628532, 0.231224, 0.140244)`. Для первого правильного класса
кросс-энтропия равна `-ln(0.628532) ≈ 0.464369`.

**BPE** учит частые сочетания символов и объединяет их в подслова.
`_` обозначает начало слова. Цифры `7` не было в обученном алфавите,
поэтому она превращается в `<UNK>`. Это обработка неизвестного символа,
а не неизвестного слова целиком. Порядок слияний сохраняется, потому что
поздние правила могут использовать результаты предыдущих.

**Count LM** считает продолжения по двум предыдущим словам.
Для незнакомого контекста она отступает к одному слову, затем к униграммам.
В примере `silent garden` неизвестна пара, но слово `garden` известно,
поэтому модель использует его счётчик и выбирает `gate`.

Для вычисления вероятностей применяется add-one сглаживание.
Оно даёт положительную вероятность даже неизвестной цели `<unk>`.
Здесь это отдельный механизм: `<unk>` Count LM и `<UNK>` BPE различаются.
Жадная генерация пяти токенов после двух слов контекста даёт:
`the garden gate opens at dawn the`.
Последнее `the` появляется из статистики непрерывной обучающей строки,
где нет специальных маркеров границ предложений.

## Что означают метрики и их ограничения

**Перплексия** оценивает вероятность истинных тестовых токенов по их
истинной предыдущей истории. В сопоставимых условиях меньшая PPL означает
меньшую среднюю неожиданность. Значение 5,63 не является процентом ошибок
и не доказывает фактическую правильность генерации.

Заданная тестовая фраза уже содержится в обучающем тексте. Поэтому здесь
PPL используется для проверки реализации; для оценки обобщения потребовался
бы независимый тест. Маленькая train loss классификатора также не заменяет
проверку на новых размеченных документах.

**ROUGE** считает лексическое перекрытие с эталоном. В кандидате A есть
все шесть слов эталона с нужными кратностями, поэтому ROUGE-1 равен 1.
Совпали три из пяти биграмм, поэтому ROUGE-2 равен 0,6.
Высокие значения не доказывают истинность: отрицание может изменить смысл,
оставив почти все прежние слова.

**Лайкерт** — отдельная ручная оценка. Для A предложены баллы:
связность 1, информативность 1, фактологическая точность 0.
Текст понятен, но выражение `near garden` не вполне естественно;
событие кратко описано, а факты полностью подтвердить по одному эталону нельзя.
Эти баллы обоснованы в ноутбуке и не вычисляются из ROUGE.

**Elo** обновляет рейтинг после попарного сравнения. Сумма рейтингов здесь
сохраняется, поскольку оба участника получают противоположные изменения.
После трёх матчей Bakery-LM формально впереди, но у всех по одной победе
и одному поражению. Разрыв мал и зависит от порядка матчей, поэтому
устойчивое превосходство не установлено.

## Как повторить запуск

Распакуй архив целиком. Открой ноутбук в Jupyter, VS Code или Google Colab.
В рабочей папке должна быть структура:

```text
ЛР_3_Основы_языковых_моделей.ipynb
data/
    greenfield_town.json
```

Для локального Python-окружения установи зависимости:

```bash
python -m pip install -r requirements.txt
```

Сам интерфейс Jupyter при необходимости устанавливается отдельно.
В Colab создай папку `data` и загрузи в неё JSON, затем выполни все ячейки.
После установки библиотек интернет для вычислений не нужен.

Полный запуск проверен на Python 3.14.4, PyTorch 2.14.1, NumPy 2.4.0
и matplotlib 3.11.2. При другой версии окружения последние цифры
обученных весов и сходств могут немного отличаться.
Все обязательные выводы и графики уже сохранены в ноутбуке.
Папка `results` дополнительно содержит экспорт результатов проверенного запуска.
